# TraceGate Studio local performance record

Measured on 2026-07-10T16:18:04Z. Raw machine-readable output is in
[`performance-results.json`](performance-results.json), generated by:

```bash
uv run python scripts/benchmark_studio.py \
  --files 100 1000 \
  --output docs/performance-results.json
```

## Environment and method

- macOS 26.5.1, arm64 (`platform.processor() = arm`)
- Python 3.12.13
- temporary local Git repositories with deterministic Python files
- production `RepositoryIndexer`, SQLite persistence, Repository Map, and
  Review Map paths
- one warm-free run per size; results are smoke measurements, not latency
  percentiles

| View cap reached | no | yes |

The 1000-file Review Map reached the intentional 800-node response cap. This
is evidence that the cap is active, not evidence that a 1000-file graph is
fully visible at once.

## Browser and idle process observations

The local in-app browser reloaded the Vite development client, observed the
real loading state, and waited until the authenticated dashboard data replaced
it. The measured wall-clock upper bound was **157 ms**. This includes browser
control overhead and is not a standardized Core Web Vital.

With the FastAPI Sidecar running against a migrated SQLite database, background
monitoring paused, and no Relay configured, five one-second `ps` samples of the
Python worker were each **0.1% CPU**. The worker RSS at the first sample was
**114,512 KiB**. The `uv` parent sampled at 0.0% CPU. This is a short idle smoke
observation, not a long-duration energy study.
